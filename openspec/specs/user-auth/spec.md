# user-auth Specification

## Purpose

Учётка заводится по Telegram-аккаунту, без почты и пароля. Сессия живёт в httpOnly cookie, поэтому каталог открывается и внутри Telegram, и как отдельное приложение на телефоне.

## Requirements

### Requirement: Учётка по Telegram-аккаунту

Система MUST связывать учётку с Telegram user id. Новая учётка MUST заводиться только активацией приглашения (см. `user-invites`), за единственным исключением: аккаунт из `BOT_ADMIN_ID` MUST получать учётку `OWNER` при первом входе, если её ещё нет. Вход из Mini App или браузера MUST NOT заводить учётку незнакомому аккаунту.

Повторный вход тем же аккаунтом MUST попадать в ту же учётку, а не заводить новую. Пароль и почта MUST NOT требоваться.

Учётка MUST иметь роль из набора `OWNER` | `ADMIN` | `USER` (см. `access-control`). Учётка по приглашению MUST получать `USER`.

#### Scenario: Первый вход заводит учётку

- **GIVEN** у аккаунта из `BOT_ADMIN_ID` ещё нет учётки
- **WHEN** он входит впервые из Mini App или браузера
- **THEN** заводится учётка с ролью `OWNER`; любому другому аккаунту первый вход учётку не заводит

#### Scenario: Вход без приглашения отклонён

- **GIVEN** у Telegram-аккаунта нет учётки и он не активировал приглашение
- **WHEN** он открывает Mini App или входит виджетом в браузере
- **THEN** система отказывает с текстом «Доступ по приглашению» по-русски, учётка и сессия не заводятся

#### Scenario: Вход после приглашения

- **GIVEN** друг активировал приглашение в боте
- **WHEN** он открывает Mini App или входит виджетом в браузере
- **THEN** он попадает в свою учётку с пустым каталогом

#### Scenario: Повторный вход не плодит учётки

- **GIVEN** аккаунт уже входил и завёл каталог
- **WHEN** он входит снова
- **THEN** открывается тот же каталог, вторая учётка не создаётся

### Requirement: Вход из Mini App

Система MUST принимать вход из Telegram Mini App по подписи `initData`. Подпись MUST проверяться на сервере; просроченная или неверная подпись MUST отклоняться. Успешный вход MUST выдавать сессию, а не разовый доступ.

#### Scenario: Подделанная подпись отклонена

- **WHEN** приходит `initData` с неверной подписью
- **THEN** система отвечает отказом и не заводит учётку и сессию

### Requirement: Вход из браузера

Система MUST давать войти по Telegram-аккаунту вне Telegram — из обычного браузера и из установленного на телефон приложения. Вход MUST приводить к тому же каталогу, что и вход из Mini App тем же аккаунтом.

Пока пользователь не вошёл, система MUST показывать экран входа по-русски, а не пустой каталог и не сообщение «откройте из Telegram». Если вход отклонён потому, что у аккаунта нет приглашения, экран входа MUST показывать это по-русски, а не общую ошибку.

#### Scenario: Один каталог из двух входов

- **GIVEN** автор завёл каталог из Mini App
- **WHEN** он входит тем же Telegram-аккаунтом из браузера
- **THEN** он видит тот же каталог со своими фразами

#### Scenario: Гость видит экран входа

- **WHEN** каталог открыт вне Telegram без сессии
- **THEN** показан экран входа по-русски

#### Scenario: Гость без приглашения видит причину

- **GIVEN** у аккаунта нет учётки
- **WHEN** он пытается войти
- **THEN** экран входа показывает «Доступ по приглашению» и подсказку попросить ссылку у автора

### Requirement: Сессия и выход

Сессия MUST храниться в httpOnly cookie и MUST NOT лежать в `localStorage`. Короткая сессия MUST продлеваться тихо, без повторного входа. Выход MUST завершать сессию на сервере, после него защищённые запросы MUST отклоняться.

Запрос без действующей сессии и без действующей подписи Mini App MUST получать отказ.

#### Scenario: Тихое продление

- **GIVEN** автор давно держит каталог открытым и короткая сессия истекла
- **WHEN** он листает карусель
- **THEN** сессия продлевается сама, экран входа не показывается

#### Scenario: После выхода доступа нет

- **GIVEN** автор нажал «Выйти»
- **WHEN** отправляется запрос к каталогу
- **THEN** система отвечает отказом и показывает экран входа

### Requirement: Управление базой по правам

Управление базой (посев, парсинг чата владельца, очистка) MUST требовать соответствующие права `db:seed`, `db:parse`, `db:clear` (см. `access-control`). Пользователь без нужного права MUST NOT запускать эти команды, ни в боте, ни через API. Отказ MUST быть по-русски и MUST NOT менять данные.

#### Scenario: Друг не управляет базой

- **GIVEN** вошёл пользователь с ролью `USER`
- **WHEN** он вызывает команду управления базой
- **THEN** система отказывает по-русски и ничего не меняет в базе

#### Scenario: ADMIN без разрушающих прав

- **GIVEN** вошёл пользователь с ролью `ADMIN`
- **WHEN** он вызывает очистку базы
- **THEN** система отказывает по-русски и ничего не меняет в базе
