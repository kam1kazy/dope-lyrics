## Why

Каталог умеет читать и класть на полки, но фраза всё ещё «просто текст»: из неё не видно, **каким куском песни** она может стать. Без роли, настроения и подачи нельзя ни отфильтровать «дай панчи в хук», ни увидеть состав сумки, ни потом честно собрать трек или кормить ИИ. Пока карточку доводим (дорожка D), нужен **профиль без модели** — как аналитика youways: сначала сигналы и полки, генерация отдельно.

Единица разметки — не три плоские грани на сообщение, а **роль в песне** (куплет, хук, …) со своим настроением и подачей. Та же нарезка потом кормит конструктор: собирать трек по кускам, а не из «всех тоскливых строк подряд».

## What Changes

Поэтапно. Этот change закрывает **MVP 1 и MVP 2**. Конструктор трека в код не входит: меняем контракт данных и сводки так, чтобы он на них сел.

### MVP 1 — профиль в карточке (уже в коде, спека догоняет)

- Готовность — одно значение на фразу. Словари:
  - **настроение:** агрессия, тоска, ирония, нежность, бравада, тревога, холод, эйфория;
  - **подача:** панч, флоу, хук, spoken, напев, адлиб, скороговорка;
  - **роль:** куплет, хук, бридж, интро, сцена, панчлайн, скетч;
  - **готовность:** строка, фрагмент, блок, текст, готово.
- Несколько ролей на одну фразу. У **каждой роли** свой набор настроения и подачи. Настроение/подача без роли — отдельный запасной набор.
- Таб «Профиль» в карточке; полки: скрыть, избранное, эталон, **цензура**. «Готово» ставится только вручную и сразу прячет фразу с карусели.
- Seed не затирает профиль. Настроение, подача, роли при загрузке не заполняются. Готовность новых записей — по длине текста; «готово» формула не ставит.
- Фильтры: роль сужает кусок; настроение и подача при выбранной роли ищутся **в этой роли**, не «где угодно на фразе».

### MVP 2 — аналитика каталога без ИИ

- Сводка корпуса: сколько фраз; полки эталон / избранное / скрыто / **цензура**.
- Покрытие: сколько фраз с хотя бы одной ролью (и отдельно — только готовность / только набор без роли).
- Разложение **по ролям** (куски): сколько фраз с куплетом, с хуком, … Фраза с двумя ролями входит в оба ряда.
- Внутри роли — разложение настроения и подачи. Глобальный COUNT по плоским `mood`/`delivery` как главная цифра — нет: соврёт конструктору.
- На карточке — текущие булевы полки, без счётчика переключений.

### Очередь после этого change (не делать сейчас)

- Конструктор / «готовый трек»: случайная или ручная склейка **из кусков по роли** (та же выборка, что сводка и фильтр). Лайк склейки как сигнал.
- События карусели (показ, скип).
- ИИ, авторазметка настроения/подачи/роли.
- Энергия 1–5 как пятая грань.

## Capabilities

### New Capabilities

- `lyric-facets`: профиль сообщения вокруг ролей в песне, таб в карточке, полка цензуры, фильтр по кускам.
- `catalog-analytics`: сводка корпуса без модели — полки включая цензуру, покрытие, разложение по ролям и по настроению/подаче **внутри роли**.

### Modified Capabilities

- Нет существующих спек в `openspec/specs/`.

## Impact

- Prisma: массивы `mood` / `delivery` / `songRole`, JSON `roleProfiles`, `isCensored`, `readiness`. Persist чата пишет только готовность по длине на новых записях.
- GraphQL: профиль, `updateLyricProfile`, фильтры `lyrics(...)`, позже `catalogStats` с рядами по ролям.
- Клиент: карточка, drawer, меню каталога; сводка — MVP 2.
- Telegram, бот, Mini App, auth, `guide/` — без изменений.

## Non-goals

- ИИ, автозаполнение настроения/подачи/роли, запись в Telegram. Готовность по длине — исключение (не модель).
- UI конструктора трека и лайки склеек в этом change. Форма профиля и сводки **должны** быть пригодны как выборка кусков.
- Свободный текст «вайб», дубль тем поверх хештегов.
- Tenant, JWT, полировка UI как финальный дизайн.
