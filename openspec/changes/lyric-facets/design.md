## Context

Мотивация — `proposal.md`. Сейчас `Lyrics` несёт полки `isReference` / `isFavorite` / `isHidden` и текст в `Message`; фильтры списка — `lyrics-list-filters.ts` и `lyrics(...)` в `server/src/graphql/typeDefs.ts`. Карточка — `client/src/features/message-desk/ui/message-desk-dialog.tsx` (текст + три кнопки полок, табов нет). Меню каталога — `catalog-menu.tsx`: живые избранное и демки, эталоны/ИИ — заглушки. Telegram в этом change не участвует: только GraphQL и Postgres.

Аналитика youways (CQI/SHI) здесь **не копируется формулами**. Берём приём: сырые флаги → COUNT/доля на сервере → экран. Весов и байеса в MVP 2 нет.

## Goals / Non-Goals

**Goals:**

- Четыре nullable поля профиля на `Lyrics`, словари в одном модуле сервера, проверка на мутации.
- Таб в существующей карточке, фильтры в существующем drawer, сводка в меню каталога.
- Один SQL-агрегат на сводку, без выгрузки всего корпуса на клиент.

**Non-Goals (дизайн):**

- Новые npm-пакеты, отдельный микросервис, JSONB «на будущее».
- Prisma enum в БД (добавление словаря = лишняя миграция).
- Компоненты kit shadcn править; Tabs из kit, если файла нет — локальный переключатель в диалоге.
- События карусели, склейка трека, запись в Telegram.

## Decisions

### 1. Поля на `Lyrics`, не отдельная таблица

Четыре колонки `mood`, `delivery`, `songRole`, `readiness`: `String?`. Пусто = `NULL`.

Альтернатива: таблица `LyricProfile` 1:1 — лишний join на каждый `lyrics`. JSON — хуже фильтровать и индексировать. Отдельная таблица имеет смысл, когда появятся события карусели / лайки склеек; не сейчас.

### 2. Словарь в коде, не enum Postgres

Константы + union TypeScript в `server/src/modules/lyrics/` (например `lyric-facets.ts`). GraphQL — `enum` с теми же ключами (латиница в API: `LONGING`, UI: «тоска»). Мутация отвергает неизвестное значение.

Альтернатива: Prisma `enum` — жёстче на уровне БД, но каждое новое слово настроения = миграция. Для личного каталога словарь ещё поедет.

Ключи стабильные, подписи только в UI.

### 3. Мутация отдельно от `updateLyricFlags`

`updateLyricProfile(id, mood, delivery, songRole, readiness)`: каждое поле опционально; явный `null` снимает грань. Полки не смешивать с профилем — разные задачи и кэш Apollo.

Фильтры списка: опциональные аргументы `mood`, `delivery`, `songRole`, `readiness` в `lyrics(...)`, И в `buildLyricsWhere` по аналогии с `referencesOnly`.

### 4. Сводка одним query

`catalogStats`: скаляры полок + покрытие + массивы `{ value, count }` по четырём граням. Считать `groupBy` / SQL в `lyrics.service.ts`, не в резолвере. Фильтры карусели на сводку не действуют (корпус целиком) — иначе «дыры» профиля зависят от текущей полки и врут.

«Как часто в эталонах» на MVP 2 = **доля флагов по каталогу**, не история togglе. Счётчик на фразу появится только если заведём события (очередь после change).

### 5. UI

- Диалог: две вкладки «Текст» и «Профиль»; футер полок общий.
- Drawer: четыре группы чипов, как теги; `data-swipe-ignore`.
- Меню: живой пункт «Сводка» (не вместо заглушки «Эталоны»). Панель с карточками чисел, без графиков как в youways.

Клиентские словари дублировать тонко: импорт констант нельзя через границу пакетов — завести те же ключи в `client/src/entities/lyric` и не разъезжаться (один список в спеке; при apply сверить вручную). Query `lyricFacetOptions` не делать в MVP: словарь крошечный.

### 6. Seed / persist

`create-lyric-data.ts` и парсер mtcute не пишут колонки профиля. Миграция: default NULL. Повторный upsert по `lyric_id` MUST не включать эти поля в `update`.

## Risks / Trade-offs

- [Пустой профиль на всём корпусе] → сводка всё равно живая по полкам; фильтр по грани даёт пустой список — нужен понятный empty state по-русски.
- [Расхождение словаря client/server] → отвергать на сервере; UI только из своего списка.
- [Сводка без фильтра] → автор на полке «избранное» видит цифры всего каталога. Это намеренно; срез «по текущему фильтру» — позже.
- [Два хука в GraphQL на одну карточку] → кэш: после `updateLyricProfile` патчить поля lyric в тех же `lyrics` queries, что и флаги.

## Migration Plan

1. Миграция Prisma (коммитить), `bun prisma generate` из `server/`.
2. GraphQL + service + фильтры.
3. Карточка и drawer (MVP 1).
4. `catalogStats` + пункт меню (MVP 2).
5. Откат: откатить миграцию / не вызывать новые поля; старые полки не зависят от профиля.
