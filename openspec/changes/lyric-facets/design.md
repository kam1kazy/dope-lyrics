## Context

Мотивация — `proposal.md`. MVP 1 в коде уже не плоские три грани: `Lyrics` несёт `mood[]` / `delivery[]` (набор без роли), `songRole[]`, JSON `roleProfiles`, `readiness`, полки `isReference` / `isFavorite` / `isHidden` / `isCensored`. Фильтры — `lyrics-list-filters.ts` (`roleFacetWhere` по JSON path). Карточка — `message-desk-dialog.tsx`. Меню — список / избранное / демки, эталоны и ИИ заглушки. Telegram в этом change не участвует: только GraphQL и Postgres.

Аналитика youways (CQI/SHI) **не копируется формулами**. Приём тот же: сырые флаги и куски → COUNT/доля на сервере → экран. Конструктор трека в MVP 2 не строится; корзины сводки = будущая выборка кусков.

## Goals / Non-Goals

**Goals:**

- Спека и `catalogStats` совпадают с ролевой моделью, уже живой в карточке и фильтре.
- Сводка одним запросом, без выгрузки корпуса на клиент. Считать куски из `roleProfiles`, не из глобального GROUP BY `mood`.
- Полка цензуры в тех же KPI, что эталон / избранное / скрыто.

**Non-Goals (дизайн):**

- UI конструктора, случайная склейка, лайки генераций.
- Новые npm-пакеты, отдельный микросервис.
- Prisma enum в БД (словари в `lyric-facets.ts`).
- Править kit shadcn.
- События карусели, запись в Telegram.

## Decisions

### 1. Кусок = роль на фразе

Источник правды для «какой это кусок песни» — `roleProfiles` (JSON-карта роль → `{ mood, delivery }`) плюс `songRole[]` как индекс включённых ролей. Корневые `mood` / `delivery` — только набор **без роли**. Сводка и фильтр при выбранной роли читают JSON, не корневые массивы.

Альтернатива «три колонки на Lyrics» отвергнута: куплет и хук на одном тексте смешивают тоску с бравадой. Отдельная таблица `LyricRoleSlot` — чище для SQL-агрегатов конструктора; не делаем в MVP 2, пока JSON path + `songRole[]` хватает фильтру. Если `catalogStats` на JSON станет хрупким — тогда нормализовать слоты, не меняя UX.

### 2. Сводка по ролям — выборка конструктора

`catalogStats` отдаёт: N фраз; полки включая `isCensored`; покрытие (есть ≥1 роль); по каждой роли — `phraseCount` и массивы `{ value, count }` для mood/delivery **внутри роли**; готовность по фразам; опционально ряд `unscoped` для набора без роли.

Фраза с двумя ролями увеличивает `phraseCount` обеих ролей. Это намеренно: конструктору нужны куски, не «уникальные сообщения с любой ролью».

Главный KPI «сколько тоски в каталоге» не строим. Если понадобится — производная от суммы по ролям + unscoped, с оговоркой о двойном счёте.

Считать в `lyrics.service.ts`. Фильтры карусели на сводку не действуют.

### 3. Словари в коде, мутации как сейчас

Ключи GraphQL латиницей (`LONGING`). `updateLyricProfile` отдельно от `updateLyricFlags` (`isCensored` во флагах). Клиентские подписи в `client/src/shared/lib/lyric-facets.ts`.

### 4. Фильтр уже задаёт семантику куска

`buildFacetWhere`: выбранные роли → `roleFacetWhere` (mood/delivery внутри роли, ИЛИ между ролями фильтра). Без ролей → ИЛИ между корневыми массивами и JSON любой роли. MVP 2 не меняет это; сводка должна быть согласована с этими корзинами.

### 5. UI сводки

Пункт «Сводка» в `catalog-menu.tsx`, не вместо заглушки «Эталоны». Карточки чисел и ряды по ролям, без графиков youways. Не кнопка «собрать трек».

### 6. Seed / готовность

Без изменения: `create-lyric-data.ts` пишет только `readinessFromLineCount` (абзац = 4 строки; 1–3 → LINE; floor(строк/4) ≤4 → FRAGMENT; ≤8 → BLOCK; иначе TEXT; READY вручную). Повторная загрузка не трогает профиль. «Готово» в карточке включает `isHidden`.

## Risks / Trade-offs

- [Двойной счёт фразы в двух ролях] → в UI подписать, что это куски, не уникальные тексты.
- [JSON path vs таблица слотов] → MVP 2 на JSON; если агрегаты врут или тормозят — слоты отдельным change.
- [Сводка без фильтра карусели] → намеренно весь корпус; срез «как в текущем фильтре» — позже / вместе с конструктором.
- [Unscoped mood без роли] → не терять, отдельная строка, не смешивать с куплетом.

## Migration Plan

1. MVP 1 (схема, карточка, фильтр, цензура, роли) — уже в коде.
2. Дописать `catalogStats` под `roleProfiles` + `isCensored`.
3. Панель сводки в меню.
4. Откат сводки: убрать query и пункт меню; профиль ролей не зависит от сводки.
