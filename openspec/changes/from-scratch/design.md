## Context

Зачем — см. proposal.md, раздел Why. Требования — `specs/ai-from-scratch/spec.md` и дельты.

Что уже есть и как устроено:

- **Вызов модели:** `server/src/modules/ai/model/model-call.ts` — `callModel` с записью в `AiUsage`, учётом на ошибке, обрывом по лимиту и ценой из `usage.cost_rub` polza.
- **Полка:** `modules/ai/artists/load.ts` — `loadArtistPool(userId, filter)` отдаёт артистов с текстами и жёсткий фильтр «Артисты» / «Тексты» (до трёх каждого). `modules/ai/artists/pick.ts` — `scoreSample(sample, songRole, facets)`: настроение ×2, энергия, подача, роль +2.
- **Правка склейки:** `modules/ai/rewrite/frame.ts` — рамка 2.2.0 (`COLLAGE_REWRITE_FRAME`); `rewrite/request.ts` — `buildRewriteUser({ theme, authorPrompt, sections })`, `contextBlocks`, `stripModelWrapper`, подписи частей `ROLE_LABELS`. Рамка работает на склейке из своих фраз, автор ею доволен.
- **Форма трека:** `modules/lyrics/track-assemble.ts` — каркас `INTRO, VERSE, HOOK, VERSE, BRIDGE, HOOK`, квоты `TrackFormQuotas` в абзацах по 4 строки, `paragraphsForRole`, второй хук копирует первый (`SECOND_HOOK_INDEX`).
- **Тексты:** `modules/track-texts/track-texts.service.ts` — `createScratchTrackText` (`slots = []`, `sourceText = ''`). `TrackText.generation` — непрозрачный JSON, разбирает клиент (`features/track-texts/lib/generation.ts`).
- **Доступ:** `requireAi(context)` в `graphql/ai.resolvers.ts` (право `ai:use`, только `OWNER`).

**Что уже сделано в ветке по варианту А** (задачи 1–8): схема `SCRATCH`, модуль `modules/ai/scratch/` (подбор трёх текстов, рамка Explore 1.0.0, запрос, сервис), мутации, страница, тексты «С нуля», скрипт `ai:scratch`. Страница, тексты, расход, мутация сохранения и скрипт остаются; подбор, рамка, запрос и ответ `writeFromScratch` меняются под вариант Б (группа задач 9).

Полка на 13.11.2026: 49 артистов, у 37 есть тексты, 352 текста (342 с прода и 10, которые принёс автор: Платина, Markul, Travis Scott), теги у всех, пояснений 0. В тексте в среднем 47 строк.

## Goals / Non-Goals

**Goals:**
- Дать модели материал: склейку из строк кумиров под грани темы, собранную кодом, без вызова модели.
- Один вызов, рамка — правка 2.2.0 с двумя заменёнными пунктами, а не новая рамка из запретов.
- Видно, где ответ слишком близок к строке кумира.
- Проверять подбор кусков и запрос без провайдера (`--pick`, `--dry`).

**Non-Goals:**
- Менять подбор и рамку «Поправить ИИ». `rewrite/frame.ts` и `rewrite/request.ts` не меняются, «С нуля» читает их.
- Подбор по смыслу темы, второй вызов на близкие строки.

## Decisions

### 1. Модуль `modules/ai/scratch/`, не режим `rewrite/`

Файлы: `pick.ts` (нарезка и подбор кусков), `frame.ts` (рамка «С нуля» на основе правки), `request.ts` (склейка → секции для `buildRewriteUser`), `close.ts` (близость строк), `scratch.service.ts` (`buildScratchRequest` без вызова и `writeFromScratch` с вызовом).

Почему отдельно, хотя рамка общая: вход другой (тема и полка против слотов из каталога), подбор другой, свой вид расхода и своя версия. Флаг режима в `rewrite.service.ts` смешал бы два потока.

### 2. Нарезка текстов на куски

`splitIntoChunks(text)`: текст делится на абзацы по пустым строкам. Абзац длиннее четырёх строк режется по четыре подряд, хвост короче трёх строк приклеивается к предыдущему куску. Текст без пустых строк режется окнами по четыре. Из куска выбрасываются строки-заглушки (`isFiller` из варианта А: пусто после скобок, метка части, одни междометия). Кусок, где после чистки меньше трёх строк, не берётся.

Ключ дубля — нормализованный текст куска (нижний регистр, без пробелов по краям, схлопнутые пробелы): совместный трек у двух артистов даёт один кусок.

Почему четыре строки: это абзац формы генератора (`PARAGRAPH_LINES = 4`), рамка правки держит четверостишие на одном звуке. Почему абзацы, а не любые окна: у текстов полки куплеты и хуки разделены пустыми строками, абзац не рвёт мысль.

### 3. Подбор кусков в склейку

`pickScratchCollage(pool, { facets, theme, quotas, chosenTextIds, artistFilter, random })` → части формы с кусками и источниками:

1. Части по каркасу `TRACK_FRAME`, число кусков — `paragraphsForRole(quotas, role)`, второй хук — копия первого.
2. Текст оценивается `scoreSample(sample, role, facets)`: для куплета роль `VERSE`, для хука `HOOK`, интро и бридж — `VERSE`. Роль снова учитывается: в варианте А её не было, а хуку нужен кусок из хука.
3. Группы по счёту сверху вниз, внутри — случайный порядок (`random` снаружи, в тестах фиксированный). Из текста берётся один случайный кусок. Куски одной части — из разных текстов. При автоподборе один текст даёт один кусок на всю склейку, артист — не больше двух. Если включён фильтр «Артисты» или «Тексты», лимит на артиста снят, а текст даёт до трёх кусков (`SCRATCH_FILTERED_TEXT_CHUNKS`). Сначала лимитов при фильтре не было вовсе: склейка из одного выбранного текста вышла бы в один кусок. 14.11 вышло обратное: один выбранный текст давал всю склейку, и модель переводила его строка за строкой (ответ по «TELEKINESIS» — 14 из 14). Цена лимита: склейка из одного текста — не больше трёх кусков, трек короче формы.
4. Выбранные тексты (`chosenTextIds`): их куски идут первыми, хотя бы один из каждого, по частям, куда они подходят по роли. Предпочитается кусок без связи, но идёт и со связью.
5. Связь (`hasLink` из варианта А) проверяется по куску: кусок со связью при автоподборе не берётся, если связи нет в теме. «Валентина» из-за «Ты ждёшь звонка» теряет один кусок, а не весь текст.
6. Не хватило кусков — часть короче, ошибки нет. Нет ни одного куска на всю склейку — ошибка «На полке нет текстов для склейки», вызова модели нет.

Отклонено: брать кусок «самый близкий по граням» внутри текста — у кусков нет своих тегов, только у текста. Подбор строк по смыслу — Non-goal.

### 4. Фильтр связи и заглушки — по куску

Регулярка связи та же, что в варианте А (`телефон|звон|набер|…|mute|\bdm\b`), но применяется к куску из четырёх строк, а не к отрывку из 24. Проблема варианта А — «Валентина» выпадала целиком из-за одной строки — уходит без порога плотности.

### 5. Рамка «С нуля» 2.0.0 — правка 2.2.0 с двумя заменами

`buildScratchSystem()` берёт `COLLAGE_REWRITE_FRAME` и меняет пункты:

- «Склейка — черновик: мотивы, слова-находки и звук. Готовых строк в ней мало.» → «Склейка собрана из строк артистов, которых любит автор. Их мир, словарь и находки бери, это и мир автора.»
- «Перепиши почти каждую строку. Дословно из склейки остаётся не больше трети строк…» → «Перепиши каждую строку. Дословно из склейки не оставляй ни одной: это чужие строки. Бери ядро — образ, слово-находку, сленг, англицизм, игру слов — и строй строку заново.»
- Пункт «Строку, которую оставляешь дословно, под звук четверостишия не подгоняй…» удаляется: дословных строк нет.
- Пункт про карточки под частью удаляется: карточек нет.

Замена — по точному тексту пункта. Тест проверяет, что каждая замена нашла свой пункт: если рамку правки перепишут, тест упадёт, и «С нуля» не уедет молча на чужие правила.

**2.1.0 (14.11):** модель читала «ядро не переводи» как «ядро оставь по-английски, остальное переведи» и тащила отсылки чужого трека (Future, Luke, troopers у Travis) — вне его трека это набор слов. Пункт «Из строки бери ядро…» заменён, к пункту «Дословно…» добавлено: перевод и калька — та же дословная строка; с английского — одно слово; имена и отсылки чужого трека — не ядро; из чужой строки — устройство удара, предмет свой.

`SCRATCH_FRAME_VERSION = '2.0.0'` — MAJOR: другой подход, чем Explore 1.0.0. Изменение рамки правки — повод проверить «С нуля» прогоном и поднять его версию.

Почему так, а не своя рамка: прогоны 13.11 показали, что стена правил «С нуля» не сходится, а рамка правки на склейке работает. Отклонено: класть в запрос целые тексты эталонов вместе со склейкой — модель снова берёт форму, а не материал, и запрос растёт.

### 6. Портрет автора подаём

`contextBlocks(theme, prompt)` — как в правке. Без портрета ответы на прогоне 13.11 были «стишком», с портретом — заметно лучше.

### 7. Запрос

`buildRewriteUser({ theme, authorPrompt, sections })`, секции — части склейки с метками `ROLE_LABELS`, без артистов (`artists: []`) и без блока эталонов. Форма трека задаётся самой склейкой: метки частей и число строк. Отдельный блок «Форма трека» не нужен.

### 8. Близость строк

`findCloseLines(answer, collage)`: строки ответа и склейки нормализуются (нижний регистр, без скобок с содержимым, без пунктуации, `ё` → `е`). Строка ответа сравнивается с каждой строкой склейки и с каждой парой соседних строк куска (модель часто сливает две строки в одну). Близко, если у них 4 слова подряд или не меньше трёх общих значимых слов — от 3 букв, без служебных («это», «твоя», «без», «тебя») — и это не меньше 0,6 от короткой строки. Результат — `[{ line, sourceLine, artistName, title }]`, номер строки — по ответу без пустых строк и меток частей.

**2.1.0 (14.11):** ещё близко, если у строки ответа и строки склейки (или пары соседних) два общих английских слова и больше — без служебных и междометий. Повод — ответ по Travis Scott «TELEKINESIS»: 14 строк из 14 — перевод или калька, сравнение по словам поймало одну, перевод меняет язык. Одно английское слово — разрешённое ядро, не близко. Чистый перевод без английских слов («Руль забери, я застыл» ← «take the wheel… I sit still») так не поймать: держит рамка 2.1.0.

Пороги — константы в `close.ts`, проверяются на примерах из прогона: «Без тебя — факап, с тобой — red flag» против «Когда нас нету — это факап / Когда мы рядом — это red flag» ловится, «Это не вино — это твоя вина, полусладкая» против «Бухой без вина, и это твоя вина» — нет.

Почему подсветка, а не второй вызов: решение автора 13.11.2026, один вызов на «Написать».

### 9. GraphQL

```graphql
type ScratchSource { textId: Int! artistName: String! title: String }
type ScratchCloseLine { line: Int! sourceLine: String! artistName: String! }
type ScratchResult {
  aiText: String!
  usageId: Int!
  sources: [ScratchSource!]!
  collage: String!
  close: [ScratchCloseLine!]!
}

writeFromScratch(theme: String!, form: TrackFormQuotas!, facets: ScratchFacetsInput, references: ReferenceFilterInput): ScratchResult!
createScratchTrackText(theme: String!, aiText: String!, usageId: Int, generation: String): TrackText!
```

`ScratchReference` / `references` из варианта А заменяются на `sources` — контракт ещё не выпущен, ломать некого. `sources` — уникальные тексты склейки в порядке появления. `collage` — текст склейки с метками частей, только для показа, в базу не идёт.

### 10. Текст «С нуля» в базе

Схема `TrackText` не меняется: `slots = []`, `sourceText = ''`. В `generation` клиент кладёт `{ kind: 'scratch', form, facets, references, picked: [{ textId, artistName, title }] }` — `picked` теперь источники склейки. Строки склейки в текст не идут (решение автора). Клиентский разбор и сводка из варианта А подходят без изменения формы.

### 11. `AiUsageKind.SCRATCH`

Аддитивная миграция уже сделана. Подпись «С нуля» в «Расходах» есть.

### 12. Клиент

Страница из варианта А остаётся. Меняется блок ответа:
- под ответом — источники «артист — трек» и кнопка-иконка «Склейка» (подсказка `Hint`), по клику раскрывается текст склейки, по умолчанию свёрнут;
- близкие строки в ответе подсвечены, по наведению — исходная строка и артист;
- `picked` для сохранения берётся из `sources`.

### 13. Прогоны

`ai:scratch`: `--pick` печатает склейку по темам (части, куски, источник у каждого куска, отметка связи), `--dry` пишет запрос. Без флагов — polza, только по слову автора.

## Проверка прогонами

**Прогон подбора кусков (без модели), до UI.** Шесть тем из куплетов автора и тема вызова 21, `--pick -n 2`. Агент сверяет склейку кода со своей ручной склейкой для темы 21 (`server/.ai-probe/scratch/t21-collage/collage.txt`). Автор отмечает куски: «годится как материал» / «мимо».
- Критерий: в склейке на тему не больше четверти кусков «мимо», ни одного со связью, хук — из текста с ролью хук.

**Прогон рамки чатом.** `--dry` на тему 21 и две темы автора, ответы пишет агент. Счётчики: строки, подсвеченные близостью; строки-продолжения; герой-жертва; автор — «хочется читать вслух».

**Проверка на polza** — по слову автора: тема 21, 2–3 вызова.

## Risks / Trade-offs

- [Узнаваемость: ядро кумира пересобрано, но строка звучит как его] → подсветка близких строк, решает автор. Пороги проверить на прогоне.
- [Грани — слабый сигнал для кусков: подбор идёт по тегам текста, не куска] → случайный кусок внутри текста, ручной выбор текстов и артистов. Если склейка мимо темы — следующий шаг теги куска или карточка артиста, не смысловой поиск.
- [Английские куски (Travis Scott) в русской склейке] → рамка правки не переводит ядро. Если английского много, ответ выходит смесью. Следить на прогоне.
- [Рамка правки меняется — «С нуля» меняется вместе с ней] → тест на точные замены, версия «С нуля» поднимается отдельно.
- [Форма «Холст» — 16 кусков, склейка и ответ длинные] → тот же `env.AI_MAX_TOKENS`, обрыв уже показывается ошибкой.

## Migration Plan

1. Миграция `AiUsageKind.SCRATCH` (сделана): только добавление значения.
2. Выкатка обычная: push в `main` по слову «в прод», CI делает бэкап БД и `prisma migrate deploy`.
3. Откат кода: страница и мутации новые, старые пути не меняются.

## История: вариант А (до 13.11.2026)

Рамка Explore 1.0.0 писала трек с нуля по теме и трём текстам-эталонам: «эталон даёт форму, тема — мир». Подбор — три текста по граням, по одному на артиста, без связи в отрывке из 24 строк. Прогоны 13.11 (`docs/research/from-scratch.md`): ответы — рассказ по порядку и герой-жертва; портрет помогает сильнее всего; три черновика 1.1.0 по правкам автора и черновик на приёмах кумиров не сошлись. Автор решил: миры кумиров брать можно, нужен материал — вариант Б.
