## Context

`AiSettingsPanel` (`client/src/features/ai-settings/ui/ai-settings-panel.tsx`) показывает всё одним запросом `AI_SETTINGS`. Версии — строки `AiPrompt` (id, text, createdAt), `savePrompt` не создаёт дубль текущего текста. Вызовы модели пишутся в `AiUsage` через `ai-usage.service.ts`, провайдер — `polza.client.ts`.

## Decisions

1. **Номер версии не хранится.** `number` = позиция среди версий пользователя по возрастанию `id` (1 — самая старая). Версии не удаляются, поэтому номер стабилен. Считается в resolver по списку, который уже читается.
2. **`name` и `description` nullable.** Старые версии без названия показываются как «Версия N» и первая строка текста.
3. **`createAiPrompt` всегда создаёт версию** с названием и описанием. Защита от дубля сохраняется: если текст, название и описание совпадают с текущей версией — возвращается текущая. Пустое название — ошибка по-русски.
4. **`suggestAiPromptMeta(text)`** — один вызов модели с короткой рамкой в коде: вернуть JSON `{ name, description }`, название до ~40 символов, описание одно предложение, ясно и по делу, допустима лёгкая ирония. Ответ парсится как `unknown` + сужение; при невалидном ответе — ошибка по-русски. Вызов пишется в `AiUsage` с kind `PROMPT_META` (OK и ERROR), версия промпта не привязывается. Пустой текст — отказ до вызова модели.
5. **Табы — свой компонент** в `features/ai-settings/ui` на кнопках (`role="tablist"`), без Radix и без правки kit. Состояние активного таба локальное.
6. **Один запрос `AI_SETTINGS`** остаётся; клиент режет «4 последние» из списка версий.

## Risks

- Модель вернёт не JSON → срез кодового блока, затем сужение; иначе ошибка и поля остаются ручными.
- Миграция только добавляет nullable-колонки и значение enum — данные не трогаются.
