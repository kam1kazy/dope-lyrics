## Context

Ответ ИИ в генераторе показывает `BeforeAfterText` (`client/src/shared/ui/before-after-text/index.tsx`): общий переключатель «Стало / Было», клик закрепляет за абзацем другой вариант, двойной клик правит пару строк (`onAfterChange`), свайп открывает меню блока. Блоки «было ↔ стало» сопоставляет `pairRewriteBlocks`. Тот же компонент стоит в сохранённом тексте (`client/src/features/track-texts/ui/track-text-view.tsx`), где его поведение менять не надо.

Ответ живёт в состоянии `collage-rewrite-panel.tsx` (`result: { sourceText, aiText, usageId }`). «Ещё раз» повторяет `rewriteCollage`. Сервер: мутация `rewriteCollage` в `server/src/graphql/ai.resolvers.ts`, модуль `server/src/modules/ai/` — `model/` (`callModel` пишет `AiUsage` и на ошибке, обрыв по лимиту — ошибка), `prompt/` (текущий промпт автора), `rewrite/` (рамка 2.0.0, сборка запроса). Виды запросов — enum `AiUsageKind` (`COLLAGE_REWRITE`, `PROMPT_META`, `REFERENCE_SELECT`), подписи — `client/src/features/ai-settings/ui/usage-tab.tsx`.

## Goals / Non-Goals

**Goals:**

- Гарантия на сервере: неотмеченные, зелёные строки и метки частей в новом ответе совпадают с прежними буква в букву, число и порядок строк те же.
- Режим пометок — включаемый в `BeforeAfterText`; в «Текстах» поведение компонента прежнее.
- Правка по пометкам — отдельный этап рядом с `rewrite/`, вызов через `callModel`, своя рамка и версия.

**Non-Goals:**

- Общий движок этапов, хранение меток в базе, история правок по пометкам.
- Карточки приёмов артистов в запросе пометок (см. решение 4).

## Decisions

### 1. Модель возвращает только красные строки, ответ собирает сервер

Модель отвечает JSON `{"lines":[{"n":<номер>,"text":"<строка>"}]}` — только по красным номерам. Сервер берёт прежний `aiText`, заменяет красные строки на присланные и возвращает собранный текст. Лишние номера и изменения других строк отбрасываются. Нет строки для красного номера, пустая строка, перенос строки внутри `text`, невалидный JSON → `AiProviderError`, ответ не показывается, токены учтены (`callModel`).

Альтернатива: модель возвращает весь текст, сервер сверяет построчно. Отклонено: модель склеивает и разбивает строки, и сверка по номерам ломается. Нужна была бы эвристика сопоставления — гарантия была бы не гарантией.

### 2. Строка = индекс в `aiText.split('\n')`

Клиент и сервер нумеруют строки одинаково: индекс в `aiText.split('\n')`, считая пустые строки и метки частей. Метить можно только непустую строку, которая не метка части (`/^\[.+\]$/` после trim). Сервер проверяет каждую метку: индекс в диапазоне, строка метится; иначе ошибка по-русски. Модели строки уходят с номерами `n` из того же индекса.

### 3. Контракт GraphQL

```graphql
enum LineMark { RED GREEN }
input LineMarkInput { line: Int!, mark: LineMark! }
type LineMarksRevision { aiText: String!, usageId: Int! }

reviseMarkedLines(aiText: String!, marks: [LineMarkInput!]!, theme: String): LineMarksRevision!
```

Склейку на сервер заново не шлём: правится уже показанный ответ. `sourceText` клиент держит у себя и не меняет. Доступ — `can(user, 'ai:use')`, как у `rewriteCollage`. Без красной метки — ошибка «Отметьте красным хотя бы одну строку».

### 4. Запрос модели: текст с пометками, без карточек

User-сообщение: тема (если есть), промпт автора (как в `rewrite/request.ts` — персонаж и вкус, не запрет правки), затем весь ответ построчно: `n | метка | строка`, где метка `R` (переписать), `G` (автору нравится — ориентир вкуса, не трогать), `·` (не трогать). Соседние строки нужны модели, чтобы держать звук четверостишия и смысл.

Рамка — `server/src/modules/ai/line-marks/frame.ts`, своя версия `LINE_MARKS_FRAME_VERSION = '1.0.0'`. Правила — короткая выжимка из рамки 2.0.0, применимая к одной строке: взять ядро строки и построить заново; держать ударную гласную конца, как у соседних строк четверостишия; без затычек и бытового репортажа; не смягчать; англицизм и растяжку не переводить; одна строка на номер. Примеров из склеек в рамке нет. Карточки приёмов не кладём: точечная правка не должна тащить в строку новый приём, ориентир — зелёные строки и соседи.

Альтернатива: переиспользовать рамку 2.0.0 целиком. Отклонено: она про пересборку всего трека («дословно не больше трети»), для двух строк это вредное давление.

### 5. Модуль `ai/line-marks/`

- `frame.ts` — рамка и версия.
- `request.ts` — разбор и проверка меток, сборка user-сообщения, разбор JSON ответа (`zod`), сборка итогового текста. Чистые функции под тесты.
- `line-marks.service.ts` — `reviseMarkedLines(userId, input)`: проверки, текущий промпт (`prompt/ai-prompt.service.ts`), `callModel({ kind: 'LINE_MARKS', … }, parse)`.

`parse` у `callModel` сразу собирает итоговый текст из ответа: ошибка разбора проходит тем же путём, что пустой ответ правки.

### 6. `AiUsageKind.LINE_MARKS`

Миграция `ALTER TYPE "AiUsageKind" ADD VALUE 'LINE_MARKS'` (как `20261111104000_ai_usage_reference_select`). Подпись в `usage-tab.tsx`: «Правка по пометкам».

### 7. `BeforeAfterText`: режим пометок

Новые необязательные пропсы: `marks: ReadonlyMap<number, 'red' | 'green'>` (ключ — индекс строки в `after`) и `onToggleMark(line: number)`. Если `onToggleMark` задан:

- короткий клик по строке «стало» → `onToggleMark(индекс)`; клик по метке части и пустой строке ничего не делает;
- зажатие блока дольше ~350 мс без сдвига → блок показывает «было», пока палец или кнопка зажаты; отпускание → «стало»; после зажатия клик не засчитывается как пометка;
- меню блока (три точки, свайп), двойной клик-правка и закрепление абзаца кликом выключены;
- общий переключатель «Стало / Было» и подсветка изменений остаются.

Индекс строки в `after` для отрисованной строки берётся из блока: `pairRewriteBlocks` сейчас режет абзацы по `\n{2,}` и теряет смещения, поэтому `RewriteBlock` получает `afterLine` — индекс первой строки абзаца «после» в `after.split('\n')` (у пустого «после» — `-1`). Строка блока `i` → `afterLine + i`. Тест `pair-blocks.test.ts` дополняется проверкой `afterLine` при нескольких пустых строках между абзацами. Если `onToggleMark` не задан, компонент ведёт себя как сейчас — так в `track-text-view.tsx`.

Цвета меток: красная — `bg-red-500/15` с левой полосой, зелёная — `bg-emerald-500/15`; они не совпадают с подсветкой изменений (`bg-yellow-400/25`, `bg-rose-400/20`) и со швом в «Текстах».

### 8. Состояние в `collage-rewrite-panel.tsx`

`marks` — состояние панели рядом с `result`. Новый ответ `rewriteCollage` («Поправить ИИ») сбрасывает все метки. Ответ `reviseMarkedLines` заменяет `aiText`, снимает красные, оставляет зелёные (индексы не сдвигаются — решение 1). «Сохранить в тексты» шлёт `aiText` без меток, как сейчас. Кнопка «Ещё раз» убирается, на её месте «Внести правки» (иконка, подпись в `Hint`), активна при ≥1 красной.

## Risks / Trade-offs

- [Модель шлёт строку длиннее или с другим звуком, чем соседи] → рамка просит держать ударную гласную конца; если не попала — автор пометит снова.
- [Красную строку переписать хочется в две строки] → не поддерживаем, 1:1 держит индексы и гарантию. Растянуть — правкой в «Текстах».
- [Зажатие на тачскрине конфликтует со скроллом] → зажатие засчитывается без сдвига больше 8 px (как `DRAG_START_PX`), иначе это скролл.
- [Потеря двойного клика-правки в генераторе] → правка руками остаётся в «Текстах» после сохранения; так решено в roadmap.
- [Метки пропадают при перезагрузке страницы] → как и сам несохранённый ответ; хранить не нужно.

## Migration Plan

Миграция только добавляет значение enum, откатывать не нужно (старые записи не трогаются). Выкатка — обычная: `develop` → «в прод» → CI применяет миграцию.
