## Why

Каталог хочется дать друзьям, но сейчас он однопользовательский не только по входу, но и по данным: запись всегда пишется на `owner.id`, чтение по владельцу не фильтруется, а история карусели и склейки вообще без владельца. Пустить второго человека до изоляции — смешать чужие тексты в один корпус.

Вход тоже упирается: в production GraphQL принимает только подписанный Telegram `initData` с `user.id === BOT_ADMIN_ID` (ADR 0007). Для друзей и для запуска с телефона вне Telegram нужна учётка и сессия.

## What Changes

- **BREAKING**: каталог, полки, профиль, генератор, история карусели, склейки и сводка становятся **личными**. Запись видна только владельцу; общего корпуса нет.
- `LyricCollage` и `CarouselHistory` получают владельца (сейчас его нет вовсе). Миграция отдаёт всё существующее текущему владельцу (`Users.id = 1`).
- Учётка заводится **через Telegram**: вход из Mini App по `initData`, вход из браузера через Telegram Login Widget. Пароля и почты нет.
- Сессия — httpOnly cookie с refresh (модель youways, ADR 0003), поэтому каталог открывается как PWA вне Telegram.
- Три роли в БД: `OWNER`, `ADMIN`, `USER`. `BOT_ADMIN_ID` при миграции становится `OWNER`, а не единственным пропуском. Права выводятся из роли матрицей в коде; операция проверяется правом, не сравнением роли со строкой.
- `/bd` (посев, парсинг, очистка) — права `db:*`, только у `OWNER`. `ADMIN` — управление без разрушающих операций (список пользователей, смена ролей — позже). `USER` — свой каталог, канал, импорт.
- Пользователь подключает **свой** канал: добавляет бота, привязывает канал командой, и новые посты падают в его каталог. Историю канала бот не читает — ограничение Telegram, не выбор проекта.
- Импорт Apple Notes перестаёт быть админским: `/notes` работает для любого пользователя и пишет в его каталог.

## Capabilities

### New Capabilities

- `catalog-owner`: у каждой записи каталога, склейки и снимка карусели есть владелец; чтение и запись изолированы по владельцу; миграция существующих данных.
- `user-auth`: учётка по Telegram-аккаунту, вход из Mini App и из браузера, cookie-сессия с refresh, доступ к GraphQL по сессии.
- `access-control`: роли `OWNER` | `ADMIN` | `USER`, матрица «роль → права» в коде, проверка через `can()`, без экранов управления.
- `telegram-channel-ingest`: привязка личного канала пользователя к его каталогу; новые посты сохраняются владельцу канала.

### Modified Capabilities

- `apple-notes-bot-import`: импорт доступен любому пользователю, а не только `BOT_ADMIN_ID`, и пишет в каталог отправителя.

## Non-goals

- Мультитенантность, организации и RBAC курсов из youways.
- Регистрация по email и паролю, восстановление пароля, OAuth-провайдеры.
- Хранение чужих MTProto-сессий (телефон + 2FA друга) на сервере.
- Чтение истории чужого чата ботом и парсинг чужого чата по кнопке.
- Общие полки, совместный доступ к чужим фразам, публикация каталога.
- Экраны управления ролями и правами в UI: роль меняется в базе (или позже CLI), не из приложения.
- Таблицы прав в БД: матрица в коде; перенос в БД — отдельным изменением, если понадобится менять без деплоя.
- ИИ, шов, генерация — дорожка E, без изменений.
- Linux-хост, домен, прод-compose — дорожка F, отдельно.
- `guide/` не трогаем.

## Impact

- **БД**: `Lyrics.userId` (уже есть, но не используется на чтение), новые поля владельца у `LyricCollage` и `CarouselHistory`, `Users` получает Telegram-id и роль (`OWNER` | `ADMIN` | `USER`), новая таблица привязки канала и сессий. Миграция Prisma с переносом существующих строк на владельца 1 с ролью `OWNER`.
- **Сервер**: `graphql/context.ts` (сейчас отдаёт только `prisma`) начинает нести пользователя; `config/security.ts` — вход по сессии или `initData`, не только по `BOT_ADMIN_ID`; `modules/auth/permissions.ts` — матрица прав и `can()`; `modules/lyrics/lyrics-list-filters.ts` и `lyrics.service.ts` — фильтр по владельцу во всех выборках; `modules/users` — реальные учётки вместо заглушки `owner`.
- **Бот**: `mtcute/guards` — проверка права, не сравнение с `BOT_ADMIN_ID`; `/notes` и обработчики Apple Notes — маршрутизация в каталог отправителя; новый обработчик постов канала.
- **Клиент**: `app/ui/telegram-gate.tsx` перестаёт быть единственным гейтом, появляется экран входа; `shared/api/apollo-client.ts` — `credentials: 'include'` рядом с `X-Telegram-Init-Data`. Без UI управления ролями.
- **Документация**: ADR 0007 (вход только через Mini App) отменяется новым ADR; правки в `docs/roadmap.md` (дорожка F) и `docs/architecture.md`.
