## Why

Кнопка «Обновить список» спрятана в настройках фильтров, читает один чат из `BOT_CHANNEL_ID` и пишет только в каталог владельца. На стенде она к тому же не показывалась вовсе: backend не достучивался до бота в соседнем контейнере. У друзей, вошедших по приглашению, подкачки нет совсем: посты, вышедшие, пока бот лежал или ещё не был админом канала, теряются навсегда. Приглашения при этом живут только в боте. Нужна одна страница «Профиль», где пользователь видит себя, свои источники с кнопкой докачки и — если есть право — свои приглашения.

## What Changes

- Новый раздел меню «Профиль»: имя и роль учётки (только просмотр).
- Блок «Подкачка» в профиле: список источников пользователя — его привязанные через `/channel` каналы, у владельца ещё и основной чат. По каждому источнику — сколько новых сообщений можно забрать, кнопка «Докачать» и понятная причина, если источник недоступен.
- Докачка читает историю привязанного канала сеансом владельца, если у этого сеанса есть доступ к каналу (публичный канал или канал, где аккаунт состоит). Закрытый канал без доступа помечается «История недоступна», новые посты по-прежнему приходят сами.
- Фразы докачиваются в каталог того, кто нажал, а не владельца.
- Блок «Приглашения» для `ADMIN` и `OWNER`: создать ссылку (с копированием), список действующих со сроком, отозвать. `USER` блок не видит.
- **BREAKING (GraphQL)**: поля `lyricIngestPreview` и `ingestPendingLyrics` заменяются на пер-источниковые; кнопка «Обновить список» уходит из настроек фильтров.
- Связь backend → бот работает между контейнерами и закрыта общим токеном: бот слушает внутреннюю сеть, а не только `127.0.0.1`.
- Дубликаты при докачке считаются по паре «чат + id сообщения», как уже требует `telegram-channel-ingest`, а не по одному id на весь каталог. Заметки Apple Notes и склейки не останавливают поиск новых сообщений.

## Capabilities

### New Capabilities

- `user-profile`: страница профиля — данные учётки, подкачка по своим источникам, приглашения из веба для `ADMIN`/`OWNER`.

### Modified Capabilities

- `telegram-channel-ingest`: пропущенные посты привязанного канала можно докачать из профиля, если сеанс владельца видит историю канала; требование «История канала не читается» смягчается до «бот сам историю не читает, недоступный канал объясняется».

## Non-goals

- Редактирование имени, аватар, смена роли, удаление учётки.
- Привязка и отвязка канала из веба — по-прежнему `/channel` в боте.
- Импорт Apple Notes из веба.
- Вход сеанса пользователя (телефон/код) ради чтения его закрытого канала.
- Автоматическая фоновая докачка по расписанию.
- Управление чужими приглашениями и пользователями (админка).
- Перенос «Выйти» из меню.
- ИИ, шов, генерация. `guide/` не трогаем. Полировка UI — прототип.

## Impact

- **Сервер**: `server/src/mtcute/ingest-http.ts` (источники, пользователь в запросе, токен, bind-адрес), `fetch-new-history.ts` (дедуп по чату, дата страницы в секундах), `lyrics.service.ts` (`loadNewRecords` по чату), GraphQL `typeDefs`/`resolvers`/`ingest-client.ts`, `invites.service.ts` наружу через GraphQL, `config/env.ts` (`INGEST_HOST`, `INGEST_TOKEN`).
- **Клиент**: новый раздел меню и фича `user-profile`; удаление `CatalogIngest` из `filter-panel`.
- **Прод**: `docker-compose.prod.yml` — адрес бота для backend и bind бота; новый секрет `INGEST_TOKEN` в `server/.env` (вписывает автор).
- **Зависимость**: change `invite-only-signup` должен быть заархивирован первым (его `user-invites` — база для веб-приглашений).
- **БД**: колонка `Lyrics.chatId` с бэкфиллом из `Chat.id`; частичный уникальный индекс `(userId, source, lyric_id)` заменяется обычным с `chatId` — он мешал одинаковым номерам из разных чатов и ронял разделение фраз.
