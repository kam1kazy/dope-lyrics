## MODIFIED Requirements

### Requirement: История канала не читается

Бот MUST NOT сам читать прошлые сообщения канала: при привязке в каталог попадают только новые посты. Пропущенные посты MUST докачиваться только по явному действию пользователя в профиле (см. `user-profile`) и только если история канала доступна для чтения. Если история недоступна, система MUST объяснять по-русски, что старые посты забрать нельзя, а новые приходят сами.

Система MUST NOT просить у пользователя телефон, код или пароль от его Telegram-аккаунта.

#### Scenario: Ожидания по истории

- **WHEN** пользователь привязывает канал
- **THEN** бот в ответе предупреждает, что сам старые посты не подтянет, попадёт новое, а пропущенное можно докачать в профиле, если канал открыт для чтения

#### Scenario: Докачка доступного канала

- **GIVEN** привязанный канал открыт для чтения, и в нём есть посты, которых нет в каталоге
- **WHEN** пользователь докачивает его из профиля
- **THEN** эти посты попадают в его каталог с источником `TELEGRAM`

#### Scenario: Закрытый канал

- **GIVEN** привязанный канал закрыт для чтения
- **WHEN** пользователь открывает профиль
- **THEN** у канала «История недоступна», данные Telegram-аккаунта у пользователя не спрашиваются

## ADDED Requirements

### Requirement: Поиск новых не путается в чужих номерах

При поиске новых сообщений источника система MUST сравнивать только с записями того же чата в каталоге пользователя. Записи из других чатов, заметки Apple Notes и склейки MUST NOT считаться «уже загруженными» для этого источника.

#### Scenario: Заметка с тем же номером

- **GIVEN** в каталоге есть заметка Apple Notes с номером, совпадающим с id свежего поста канала
- **WHEN** пользователь открывает профиль
- **THEN** пост считается новым и входит в счётчик

#### Scenario: Тот же номер в другом чате

- **GIVEN** в каталоге есть фраза из основного чата с id 500, а в привязанном канале вышел пост с id 500
- **WHEN** пользователь докачивает канал
- **THEN** пост канала добавляется, фраза основного чата не трогается
