## Context

См. proposal.md. Карточка — `client/src/features/message-desk/ui/message-desk-dialog.tsx`: табы текст/профиль, мутации флагов и профиля, текст в `<p>`. Тело без хештегов (`withoutHashtags` при парсе). Список — Apollo `lyrics` и `update-lyrics-cache.ts`. Сервер: `lyrics.service.ts`, `typeDefs.ts`, `readinessFromLineCount`. Telegram в этом change не участвует: только GraphQL и Postgres.

## Goals / Non-Goals

**Goals:**

- Разрез и правка без миграции Prisma.
- Линия разреза по логическим строкам, не по визуальному wrap.
- Кэш списка: обновить верх, вставить низ, если проходит текущий фильтр.

**Non-Goals:**

- Слой «история правок», parent/child в схеме.
- Новый kit shadcn (alert-dialog). Диалоги — существующий Dialog.
- Перекладка `LyricCollage` `startLine`/`endLine`.

## Decisions

### 1. Разрез на месте, низ — новая строка

Исходный `Lyrics.id` становится верхом. Низ — `prisma.lyrics.create` с копией полей (теги, профиль, полки, `lyric_id`, чат, автор). Медиа и реакции не копируем: они 1:1 у исходной. Альтернатива «скрыть оригинал, две новые» плодит сироту с полным Telegram-текстом.

`afterLine` в GraphQL: индекс последней строки верха, 0-based, как `lines.slice(0, afterLine + 1)` / `slice(afterLine + 1)`. Клиент шлёт индекс стыка.

### 2. Строки = split по `\n`

Не `splitGeneratorLines` с trim-фильтром для индексации: пустые строки между куплетами сохраняем в половинах, но «непустая половина» проверяется после trim по всей половине. Кнопка разреза: ≥2 строк с `trim()`.

### 3. Готовность

Если `readiness === 'READY'` — не трогать. Иначе `readinessFromLineCount(paragraph_count)` после нового текста. Как у seed, «готово» формула не ставит.

### 4. Мутации рядом с флагами

`updateLyricText(id, text)` и `splitLyric(id, afterLine)` в `lyrics.service.ts`. Ошибки — GraphQL error с русским сообщением (как профиль). Пустой текст после правки: разрешить пустую строку или нет? Отклоняем текст из одних пробелов — иначе фраза пропадает из смысла каталога; пустой trim MUST ошибка.

### 5. UI режимы в столе

Локальный state: `view` | `split` | `edit`. Пунктир — overlay над блоком строк (каждая строка — элемент, pointer на стыках, линия не раздвигает строки). Вход в разрез — долгое нажатие по тексту; подтверждение — «Разделить», затем выбор части; `splitLyric` только после выбора верха или низа. Escape / оверлей на экране выбора закрывают выбор, не режут. Не contenteditable для разреза. Правка — `textarea`. Грязный выход — второй Dialog поверх, не `window.confirm`.

После `splitLyric` карточка переключается на выбранный id: проп `lyric` с родителя. Значит стол MUST сообщить родителю (`onLyricChange` / выбранный id в viewport и catalog list).

### 6. Кэш

Расширить `update-lyrics-cache.ts`: патч текста у id; insert новой lyric в массив `ALL_LYRICS`, если `lyricMatchesQueryShelves` + текстовые фильтры — на клиенте нет полного replay фильтра. Прагматично: вставить в текущий список, если не скрыта относительно тех же shelf-флагов, что уже есть в хелпере; остальные оси фильтра (теги, роли) у копии те же, что у верха, значит низ проходит тот же запрос, что верх. Если верх был в списке — низ тоже вставляем рядом.

## Risks / Trade-offs

- [Два ряда с одним `lyric_id`] → ingest по-прежнему skip по Set id; различать по Prisma `id`.
- [Склейки с startLine] → после разреза куски конструктора могут врать; не чиним в этом change.
- [Двойной тап на телефоне] → как просили; конфликт со свайпом карусели гасится stopPropagation, как у карточки сейчас.
- [Визуальный wrap ≠ `\n`] → одна длинная строка не режется, пока не вставить перевод.
