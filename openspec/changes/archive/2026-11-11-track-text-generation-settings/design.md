# Design

## Context

Текст (`TrackText`, `server/prisma/schema.prisma`) создаётся мутацией `createTrackText` ([track-texts.service.ts](../../../server/src/modules/track-texts/track-texts.service.ts)). Сейчас она получает склейку, тему, ответ ИИ и `hideAdlibs`. Форма трека и фильтры генератора живут только в состоянии `widgets/catalog-menu` (`generatorForm`, `hideAdlibs`, `generatorFilters`) и в панели `CollageRewritePanel`, где они уже уходят в `rewriteCollage` как `LyricPoolFilter` (не как UI-фильтры). Telegram не участвует: всё через GraphQL.

Требования: [specs/track-text-generation-settings/spec.md](specs/track-text-generation-settings/spec.md). Мотивация: [proposal.md](proposal.md).

## Goals / Non-Goals

**Goals:**
- Сохранить на тексте снимок настроек, достаточный, чтобы показать сводку и вернуть настройки в панель.
- Не ломать старые тексты и не требовать бэкфилла.

**Non-Goals:**
- Типизированная схема фильтров на сервере: сервер не интерпретирует UI-фильтры.
- Версионирование формата настроек.

## Decisions

**1. Одно необязательное поле `TrackText.generation Json?`.**
Внутри объект `{ form, hideAdlibs, filters }`. Альтернатива: колонки под каждое поле. Отвергнуто: фильтры генератора меняются вместе с интерфейсом (см. `CatalogSectionFilters`), под них пришлось бы гонять миграции. Json держит снимок «как было».

**2. Фильтры хранятся как UI-снимок (`CatalogSectionFilters`), а не как `LyricPoolFilter`.**
`LyricPoolFilter` уходит в модель, но из него нельзя вернуть панель без потерь: пропадают `shuffleSeed`, режим сортировки, сортировка по дате. Для «Применить в генератор» нужен именно UI-снимок. Альтернатива: хранить оба. Отвергнуто: сводке хватает UI-снимка, дубль без потребителя.

**3. Передача по GraphQL — строкой JSON.**
В схеме нет скаляра JSON (`typeDefs.ts`), а тянуть `graphql-scalars` ради одного поля не стоит. У `createTrackText` появляется `generation: String` (JSON), у `TrackText` — `generation: String`. Сервер только проверяет, что это JSON-объект до ~8 КБ, и кладёт его в колонку как есть; форму и адлибы не валидирует, потому что сводка и «Применить» читают их на клиенте с защитой. Альтернатива: типизированный input `TrackTextGenerationInput` с `TrackFormQuotas` и фильтрами. Отвергнуто для фильтров по той же причине, что и в п. 1; для формы он был бы лишним на фоне общего `String`.

**4. Чтение на клиенте — `unknown` и сужение, значения по умолчанию.**
Функция в `features/track-texts/lib/` разбирает строку: не объект → «настроек нет»; поля, которых нет или которые не того типа, берутся из `DEFAULT_TRACK_FORM_QUOTAS` / `DEFAULT_GENERATOR_SECTION_FILTERS`. Приведения `as` к внешним данным нет (правило `typescript.md`).

**5. Настройки пишутся только из `CollageRewritePanel`.**
Панель при «Сохранить в тексты» берёт форму, адлибы и фильтры из пропсов и сериализует. «Открыть как текст для правки» (`CatalogAssemblePanel`) настройки не передаёт: у сборки из избранного неизвестно, с чем она собиралась, подставлять текущие панели было бы ложью.

**6. «Применить в генератор» — через состояние `catalog-menu`.**
`TrackTextView` получает колбэк `onApplySettings(form, hideAdlibs, filters)`. `catalog-menu` по нему вызывает существующие `setGeneratorForm` (+ `writeGeneratorForm`), `setHideAdlibs`, `setGeneratorFilters` и закрывает текст. Склейка не пересобирается. Нового хранилища и контекста нет.

## Risks / Trade-offs

- **UI-снимок устаревает при смене набора фильтров** → читаем с дефолтами по каждому полю (требование «Повреждённые настройки не ломают текст»); добавленное поле не ломает старые тексты.
- **JSON строкой теряет типизацию на границе GraphQL** → единственный разбор на клиенте, с тестом на мусор и частичные данные.
- **Размер снимка** (теги, ключевые слова) → потолок ~8 КБ на сервере, сверх него мутация отвечает ошибкой по-русски.
- **Сводка «как было» может не совпасть с тем, что реально ушло в модель** (на модель уходит `LyricPoolFilter`, собранный из того же UI-фильтра) → допустимо: сводка показывает настройки автора, а не промпт.

## Migration Plan

1. Миграция Prisma: `ALTER TABLE ... ADD COLUMN generation jsonb NULL`; аддитивная, старые строки получают `NULL`.
2. Выкатка сервера, затем клиента. Старый клиент не передаёт `generation` — текст создаётся без настроек.
3. Откат: колонку можно оставить, новый клиент не нужен; бэкфилла нет.
