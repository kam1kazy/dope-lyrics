## Purpose

Страница «Профиль» собирает в одном месте всё, что касается учётки: кто вошёл, откуда приходят фразы и как докачать пропущенное, а для `ADMIN` и `OWNER` — приглашения друзей.

## ADDED Requirements

### Requirement: Раздел «Профиль» в меню

Система MUST показывать вошедшему пользователю раздел «Профиль» в меню каталога. Профиль MUST показывать имя учётки и её роль по-русски («Владелец», «Админ», «Пользователь»). Имя и роль MUST NOT редактироваться из профиля.

#### Scenario: Пользователь видит себя

- **GIVEN** пользователь вошёл в каталог
- **WHEN** он открывает «Профиль» в меню
- **THEN** видит своё имя и роль, полей для правки нет

#### Scenario: Без входа профиля нет

- **GIVEN** сессии нет
- **WHEN** клиент запрашивает данные профиля
- **THEN** сервер отвечает отказом, данные чужой учётки не отдаются

### Requirement: Источники подкачки

Профиль MUST показывать список источников пользователя: каждый канал, привязанный к его каталогу, а у `OWNER` — дополнительно основной чат каталога. Для каждого источника MUST показываться название и одно из состояний: число новых сообщений, «Новых нет», «История недоступна» или «Не удалось проверить». Источники другого пользователя MUST NOT показываться.

Если источников нет, профиль MUST подсказать по-русски, что канал привязывается командой `/channel` в боте.

#### Scenario: Свои каналы и счётчик

- **GIVEN** у пользователя привязан канал, в котором вышло 3 поста, которых нет в его каталоге
- **WHEN** он открывает профиль
- **THEN** видит этот канал с числом 3 и кнопкой «Докачать»

#### Scenario: Чужие источники не видны

- **GIVEN** у авторов A и B привязаны свои каналы
- **WHEN** автор A открывает профиль
- **THEN** в списке только каналы автора A, основного чата владельца нет, если A не `OWNER`

#### Scenario: Нет источников

- **GIVEN** у пользователя `USER` нет привязанных каналов
- **WHEN** он открывает профиль
- **THEN** видит подсказку про `/channel` в боте вместо списка

#### Scenario: Закрытый канал

- **GIVEN** канал привязан, но его история недоступна для чтения
- **WHEN** пользователь открывает профиль
- **THEN** у канала написано «История недоступна», кнопки «Докачать» нет, пояснение — новые посты приходят сами

#### Scenario: Бот не отвечает

- **GIVEN** бот выключен или недоступен
- **WHEN** пользователь открывает профиль
- **THEN** у источников «Не удалось проверить», профиль при этом открывается

### Requirement: Докачка в свой каталог

По кнопке «Докачать» система MUST после подтверждения добавить новые сообщения этого источника в каталог нажавшего пользователя и MUST показать, сколько добавлено. Сообщения MUST NOT попадать в чужой каталог. Повторная докачка MUST NOT создавать дубликаты. Одновременные докачки MUST выполняться по очереди, не теряя и не дублируя сообщения.

#### Scenario: Докачка добавляет пропущенное

- **GIVEN** у канала пользователя 3 новых сообщения
- **WHEN** он нажимает «Докачать» и подтверждает
- **THEN** 3 фразы появляются в его каталоге, счётчик источника становится «Новых нет»

#### Scenario: Повтор не плодит дубликаты

- **GIVEN** докачка канала только что прошла
- **WHEN** пользователь нажимает «Докачать» ещё раз
- **THEN** новых записей не появляется

#### Scenario: Ошибка докачки

- **GIVEN** во время докачки бот перестал отвечать
- **WHEN** пользователь подтверждает докачку
- **THEN** видит по-русски «Не удалось докачать», каталог не меняется наполовину молча

### Requirement: Приглашения из профиля

Пользователь с правом `users:invite` MUST видеть в профиле блок «Приглашения» и MUST мочь: создать приглашение и получить ссылку на бота с кнопкой копирования и сроком действия; видеть свои действующие приглашения с датами создания и окончания; отозвать любое своё действующее приглашение. Ссылка MUST работать так же, как созданная командой `/invite` в боте. Код приглашения MUST показываться только один раз — при создании.

Пользователь без права `users:invite` MUST NOT видеть блок, и сервер MUST отклонять его запросы на создание, список и отзыв.

#### Scenario: Админ создаёт приглашение

- **GIVEN** вошёл `ADMIN`
- **WHEN** он нажимает «Создать приглашение»
- **THEN** видит ссылку на бота, кнопку «Скопировать» и дату окончания; приглашение появляется в списке действующих

#### Scenario: Отзыв из профиля

- **GIVEN** у `OWNER` есть действующее приглашение
- **WHEN** он отзывает его в профиле
- **THEN** приглашение пропадает из списка, ссылка по нему больше не заводит учётку

#### Scenario: USER без приглашений

- **GIVEN** вошёл `USER`
- **WHEN** он открывает профиль
- **THEN** блока «Приглашения» нет

#### Scenario: USER в обход интерфейса

- **GIVEN** вошёл `USER`
- **WHEN** клиент шлёт запрос на создание приглашения напрямую
- **THEN** сервер отказывает, приглашение не создаётся

#### Scenario: Чужое приглашение не отозвать

- **GIVEN** у `ADMIN` A есть действующее приглашение
- **WHEN** `ADMIN` B пытается отозвать его по id
- **THEN** сервер отказывает, приглашение остаётся действующим
